# YoYo桥 · 部署方法

把本桥部署到**另一个 Muse 账号**里，让那个账号也能为同一台
本地画布（YoYo画布本地版）执行生成任务。桥与账号一对一：一个
账号里部署一份桥，本地画布侧为这个账号建一份档案与之配对。

## 推荐路径：交给那个账号的 Muse 自动部署

1. 在目标账号里打开它的 Muse，把本源码包（整个 zip）交给它。
2. 把同包内的 `部署提示词.md` **整段复制**粘贴给它。
3. 它会自行完成：建 Space、构建发布、建两个定时任务、自检。
4. 部署中它会向你索取两样东西——**隧道地址**和**桥令牌**，
   都从本地画布的桥管理页拿（见 `使用方法.md` 的配对三步），
   不要让它自行编造。
5. 部署完成后按 `部署提示词.md` 里的验收标准逐项核对。

## 人工核对点（自动部署完后逐项看一眼）

| 项 | 应有状态 |
| --- | --- |
| Space 名 | 显示名「YoYo桥」，slug `yoyo-bridge` |
| slug 被占用时 | 改用后缀 slug（如 `yoyo-bridge-2`），并同步改 `space.json` 的 slug；改名结果要明确告诉用户——功能不受影响，配对只认隧道地址 + 令牌 |
| 构建发布 | 以那个账号的 Space 构建通道发布成功，设置页能打开（打开 Space 即是设置页） |
| 数据库迁移 | 首次构建/启动自动执行 `drizzle/0001_initial.sql`、`0002_bridge_tables.sql`，生成 `bridge_config`、`bridge_jobs` 两表，无需手工跑 SQL |
| 定时任务一 | 名 `yoyo-bridge-sync`，每 **30 秒**，以 space_action 方式直调本 Space 的 `bridgeSync` 动作 |
| 定时任务二 | 名 `yoyo-bridge-fast`，每 **10 秒**，以 space_action 方式直调本 Space 的 `bridgeFastSync` 动作 |
| 未配对状态 | 两任务在未配对时应为准点触发、成功空转（动作回 skipped），不报错、不刷屏 |

`space.json` 里已声明 `managedCronJobs: ["yoyo-bridge-sync",
"yoyo-bridge-fast"]`，可作核对依据；若平台未自动创建，按上表
手工建齐并复核一次触发记录。

## 前置条件（不属于桥部署本身）

- 本地画布已在用户 Windows 电脑上跑起来（本地画布源码包）。
- Cloudflare 隧道已由用户在本机配好（所有账号共用同一个隧道
  地址）。隧道没配好之前桥可以先部署，配对留到隧道就绪后做，
  未配对期间桥只是空转。

## 红线

- 不改源码口径：桥是纯执行器，部署时只做「原样装上」，不增删
  动作、不改状态机、不加任何像素/比例推导逻辑。
- 桥令牌只许填进桥设置页的配对表单，**不许写进任何代码、
  文档、提交或日志**。
