# YoYo桥 使用方法（v2，2026-11-22）

## 一分钟看懂

YoYo桥是本地画布和云端生成之间的桥：你在本地画布发起生成，任务经 Cloudflare 隧道被云端领取、执行，成品再回送落回本地节点。你日常只需要看一个页面——YoYo桥设置页，它同时是状态页。

链路：本地画布 →（任务进本地待处理列表）→ 桥每 5 秒同步领取 → 云端内置管线生成 → 回送本地 → 本地节点出图。

## 配对（首次或换机时）

1. 本机先保证两样在跑：本地画布/桥服务（`127.0.0.1:3737`）、以及绑定你隧道域名的 cloudflared 隧道。
2. 本机打开 `http://127.0.0.1:3737/bridge-admin`，新建一个桥档案，拿到桥令牌。
3. 打开 YoYo桥设置页，在配对设置里填：
   - 隧道地址：你的 https 隧道地址（形态如 `https://yoyo-bridge.example.com`）
   - 桥令牌：上一步拿到的令牌（留空表示不改，只在首次或换令牌时填）
4. 点「保存配对」。页面顶部显示「已配对」且「本地最后在线」出现时间，即配对成功。令牌在页面上只显示掩码，这是正常的。

注意：配对后两个定时任务首次访问隧道域名时各弹一次网络批准（Sync / Fast 各一次），都选**始终允许**，否则同步轮次出不了网。

## 看状态

设置页顶部四格计数，页面每 **5 秒自动刷新**一次（切到后台标签会自动暂停），不用手动刷新：

| 计数 | 含义 |
| --- | --- |
| 待处理 | 已被桥领取入库、还没派发的任务（queued） |
| 在途 | 正在执行或待回送的任务（working / done） |
| 失败 | 当前处于失败状态、还没走完回送清理的任务 |
| 已完成 | 已走完整个生命周期并清理完毕的任务（cleaned） |

单个任务的状态流：**待处理 → 执行中 → 待回送 → 已回送 → 已完成**。失败的任务走 失败 → 已回送（失败原因回送本地）→ 已完成，所以看结果要结合任务行上的失败原因文字，不要只看终态标签。

速度参考：同步与页面刷新都是 5 秒节奏，新任务领取平均等约 2.5 秒；一单 1152×2048 生图从本地发起到成品落回本地，干净全程约 58 秒。

## 日常操作

- **发起任务**：在本地画布里正常发起生成即可，桥自动领取，不需要来设置页点任何东西。前提是本地画布当前档案已设为要用的那个桥档案。
- **在本地停止任务**：照常在本地停。桥这边不需要手动处理——如果任务还没被派发，它会短暂留在「待处理」，随后被对账机制自动结算（见下节），最多一轮全量同步 + 60 秒宽限。
- **清除失败记录**：失败记录会留在任务列表里（含已完成但仍带失败原因的行）。设置页有「清除失败记录」入口，上面标着可清除条数，点后需二次确认才真删。
- **清除配对**：点「清除配对」会弹窗，必须手动输入 `yes` 才能执行。清除后隧道地址与令牌一并抹掉、桥回到未配对、同步开始空转；恢复配对要重新拿令牌（云端只存掩码，清了找不回），没事不要点。

## 孤儿对账（自动，不用管）

本地停止/取消一个已被桥领取、但还没派发的任务时，它会从本地待处理列表消失。桥在每轮全量同步里做对账：以本轮成功拉到的本地列表为准，不在列表里、且超过 60 秒没被动过的待处理行，自动结算为失败（原因写明「本地已取消该任务…自动结算（未执行）」），再走正常回送走到已完成。每轮最多处理 10 条；本地不可达的那一轮不对账，不会误杀。所以看到这类行自己消失，是机制在工作，不是丢任务。

## 故障排查

先看设置页的「最近错误」和「本地最后在线」，再对表：

| 现象 | 是什么 | 怎么办 |
| --- | --- | --- |
| 最近错误含 530 / error code 1033 | Cloudflare 隧道离线，没有连接器在线 | 本机把 cloudflared 隧道重新拉起来；注意要拉绑定配对域名的那条命名隧道，临时隧道（trycloudflare 随机地址）接不上固定域名 |
| 最近错误含 502 | 隧道通了，本地源站（桥服务）异常 | 查本机本地画布/桥服务是否在跑、是否刚崩；重启本地服务 |
| 最近错误 ECONNRESET | 连接被本地侧意外关闭 | 同步能刷新在线时间却领不走任务时多半是它；查本地桥在同步时刻的处理日志，看取参考文件或 ack-claim 哪一步断的 |
| 本地最后在线一直为空 | 云端从未成功联系上本地 | 按 530/502 顺序先查隧道、再查本地服务 |
| 自己在浏览器打隧道地址 `/bridge/pending` 回 401 | 正常鉴权（没带令牌） | 不是故障，反而说明隧道与本地服务都活着 |
| 错误写「文件下载返回 404」 | 云端按任务给的路径去本地取参考文件，本地没有 | 查本地项目 `_bridge` 目录里那个中继文件在不在；在的话再看路径是否出现双斜杠（如 `_bridge//relay-…`）导致对不上 |
| 任务一直待处理、更新时间每轮都刷新 | 它还活着、在重试（多半是取参考文件失败） | 看最近错误定位，别当成孤儿，它不会被对账清掉 |
| 任务一直待处理、更新时间冻住不动 | 本地已把它停了，等对账即可 | 超过约 1 分钟仍不动且本地确认已停，再看同步是否在报错 |

## 红线与注意事项

- 生成只走 Muse 内置管线，**永久禁用 MiniMax Token Plan**，不要尝试改派发去用任何外部订阅额度兜底；内置做不到时任务会直接失败并写明原因，这是预期行为。
- 桥令牌不要发到聊天、文档或任何文件里；要换令牌就在本地 bridge-admin 新建档案，再回设置页保存配对。
- 同步间隔是两条都 5 秒（定版），觉得快慢不对先别自己改定时任务，找 Muse 评估。
